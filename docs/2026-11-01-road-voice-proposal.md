# 길소리: 그 길에서만 들리는 친구의 목소리

공모전 기획 초안 v0.1 · 2026-11-01

> 길 위에 짧은 음성메모를 남기고, 서로 팔로우한 사람이 같은 길에 도착했을 때만 들을 수 있는 차량용 소셜 오디오 앱.

이 문서는 아이디어 검토용 초안이다. 아래 길이·거리·운영 정책·목표 수치는 제안이며 확정 요건이나 검증된 성과가 아니다. 공모전 제출용 본문과 내부 개발 검토를 분리했다.

## 기획 판단

핵심 매력은 ‘같은 풍경을 보면서 아는 사람의 목소리를 듣는 경험’이다. 길을 정보 검색의 대상에서 사람의 이야기가 남는 장소로 바꿀 수 있다. 장소를 직접 방문해야 한다는 제약이 콘텐츠의 의미를 만든다.

다만 위치 기반 음성메모 자체만으로 독창성을 입증할 수는 없다. 경쟁 서비스 비교는 아직 수행하지 않았다. 이 기획은 서로 아는 관계, 실제 도로 방문, 차량의 오디오 경험을 결합하는 데 집중한다. 공모전에서는 ‘왜 스마트폰 지도가 아니라 차량에서 쓰는가’를 실제 시연으로 보여줘야 한다.

가장 큰 사업 위험은 첫 이용 때 아는 사람이 남긴 메모가 없다는 점이다. 초기 대상은 서로 팔로우하고 같은 코스를 방문하는 소규모 드라이브 모임으로 좁힌다. 처음부터 전국 공개형 음성 지도를 만들지 않는다.

## 1. 앱 한 줄 소개

길소리는 서로 팔로우한 사람의 음성메모를 그 메모가 남겨진 길에 직접 도착했을 때만 들을 수 있는 Pleos Connect 기반 차량용 소셜 오디오 서비스입니다.

## 2. 기획 배경

여행이나 드라이브를 하다 보면 특정 장소에서 떠오르는 기억과 감상을 가까운 사람에게 전하고 싶은 순간이 있습니다. 사진과 메시지로 내용을 전달할 수는 있지만, 상대가 같은 풍경을 보는 순간에 목소리를 듣게 하기는 어렵습니다.

길소리는 이야기를 보낸 시간 대신 이야기가 의미를 갖는 장소에서 전달합니다. 사용자는 자신이 방문한 길에 짧은 목소리를 남기고, 서로 팔로우한 사람은 나중에 같은 길을 방문해 그 이야기를 듣습니다. 함께 이동하지 않아도 같은 장소의 경험을 나눌 수 있습니다.

초기 고객은 친구·연인과 드라이브 장소를 공유하거나 동일한 코스를 서로 다른 시간에 방문하는 소규모 모임입니다. 사용자가 실제로 목소리를 남기고 다시 방문하는지는 인터뷰와 제한된 코스 실험을 통해 검증하겠습니다.

## 3. 주요 기능 및 차량 특화 요소

### 3-1. 길 위에 목소리 남기기

- 실제 방문한 도로 구간에 최대 30초 음성메모를 남깁니다. 초기 권장 길이는 10~20초입니다.
- MVP에서는 안전하게 주차한 상태에서 녹음하고 확인한 뒤 게시합니다. 운전 중 녹음·편집은 제외합니다.
- 임의의 원격 지점에 메모를 대량 배치할 수 없도록 현재 방문이 확인된 구간에만 게시합니다. 출발지와 전체 이동 경로는 공개하지 않습니다.
- 제목과 짧은 장소 설명은 주차 중에 작성합니다. 내용이 담긴 자막·요약·미리듣기는 방문 전에 제공하지 않습니다.

### 3-2. 서로 팔로우한 사람끼리 공유하기

- 초기 버전은 상호 팔로우 관계에만 음성메모를 공개합니다. 한쪽이 팔로우를 해제하거나 차단하면 청취 권한도 종료합니다.
- 팔로우 요청·수락·목록 관리는 주차 중에 합니다. 차량 밖에서는 초대 링크로 관계를 연결하는 보조 화면을 검토합니다.
- 낯선 사람의 공개 피드, 실시간 위치 공유, 방문 사실을 작성자에게 실시간으로 알리는 기능은 넣지 않습니다.

### 3-3. 그 길에서만 듣기

- 상대가 메모가 남겨진 도로 구간에 도착해야 재생할 수 있습니다. 단순히 한 번 방문했다고 영구적으로 잠금이 풀리지는 않습니다.
- 방문 전에는 허용된 사람의 메모 존재 여부만 확인할 수 있습니다. 음성, 본문 자막, 요약, 다운로드 링크는 잠겨 있습니다.
- 해당 구간에서 벗어나면 재생을 중단하고 다시 잠급니다. 재방문하면 처음부터 또는 남은 위치부터 재생할 수 있습니다.
- 위치 신뢰도가 낮거나 업데이트가 끊기면 재생을 보류합니다. 지도상으로 가까워도 다른 고가도로·평행도로라면 해제하지 않는 것이 목표입니다.
- 타인이 이미 들은 소리를 외부 기기로 녹음하는 것까지 완벽하게 막을 수 있다고 약속하지 않습니다.

### 3-4. 차량에서의 경험

차량 위치와 도로 맥락에 맞춰 음성메모를 발견하고 차량 오디오로 듣게 합니다. 차량 상태를 확인해 주행 중에는 녹음·텍스트 입력·지도 탐색·팔로우 관리를 제한합니다. 통화나 내비게이션 안내가 시작되면 재생을 양보합니다.

주행 중 음성 재생은 최종 목표이지만, 앱 분류와 Pleos 정책 검토를 거쳐 허용 여부를 먼저 확인하겠습니다. 초기 시연은 안전하게 주차할 수 있는 장소를 포함한 방문 구간으로 구성합니다. 주행 중 재생이 허용되지 않으면 같은 구간 내 안전한 주차 상태에서만 듣는 방식으로 제공합니다. 신호 대기로 속도가 0이 된 상태를 주차로 판단하지 않습니다.

## 4. 주요 사용 시나리오

### 친구가 남긴 이야기를 며칠 뒤 발견하기

1. 지민과 서연은 서로 팔로우합니다.
2. 지민은 드라이브 코스의 전망대 주차 구역에서 18초 메모를 남깁니다. “여기서 보는 바다가 좋아서 네 생각이 났어. 다음에 같이 오자.”
3. 며칠 뒤 서연은 같은 코스를 방문합니다. 출발 전에는 해당 구간에 친구의 메모가 있다는 사실만 보입니다.
4. 전망대가 포함된 지정 구간에 도착하면 위치를 확인합니다. MVP에서는 안전하게 주차한 뒤 재생 버튼이 활성화됩니다.
5. 서연은 같은 풍경을 보며 지민의 실제 목소리를 듣습니다. 이 구간을 떠나면 다시 들을 수 없습니다.
6. 서연도 그 자리에서 답하는 메모를 남길 수 있습니다. 지민은 다시 방문할 때 그 목소리를 듣습니다. 별도 대화방은 만들지 않습니다.

### 첫 사용에 콘텐츠가 없을 때

메모가 없는 지도만 보여주지 않고 ‘첫 메모 남기기’와 ‘함께 갈 친구 초대’를 제시합니다. 초기 코스 실험은 참여자들의 동의를 받아 메모를 사전에 남겨 둡니다. 운영자 예시를 실제 친구의 메모처럼 표시하지 않습니다.

## 5. 개발 계획

### 핵심 구현 범위

Pleos Connect용 Kotlin 앱에서 계정·상호 팔로우·음성 녹음·업로드·현장 청취·삭제·차단을 구현합니다. 서버는 관계와 메모 권한을 관리하고, 위치 조건을 확인한 경우에만 짧게 유효한 음성 접근 권한을 발급합니다. 실제 음성은 비공개 객체 저장소에 보관합니다.

### 활용 SDK와 역할

| 구성 요소 | 역할 | 확인한 사실과 남은 검증 |
|---|---|---|
| FusedLocation SDK | 현재 위치 수신, 구간 진입·이탈 판단의 입력 | v1.1.3 문서에 위치 콜백·근접 알림·진행 방향·신뢰도·시각이 있다. 계정의 제공 상태는 미확인이다. |
| Vehicle State SDK | 주행/주차 상태에 따른 UI·녹음 제한 | 신청 안내상 바로 사용 가능하다. 구체적인 상태 API·권한·지원 여부는 구현 전에 확인한다. |
| Android 녹음·재생 API | 실제 사람 목소리 파일 녹음·재생 | SpeechToText와 구별한다. 차량 마이크 접근·오디오 포커스·미디어 세션 통합은 실기 검증이 필요하다. |
| SpeechToText SDK | 추후 음성 입력 또는 녹음 제목 보조 | MVP 필수 아님. 텍스트 변환 SDK이며 음성 저장·명령 실행 SDK가 아니다. |
| TextToSpeech SDK | 추후 짧은 시스템 안내 | MVP 필수 아님. 친구의 실제 목소리를 TTS로 대체하지 않는다. |
| NaviHelper SDK | 추후 기존 경로와 메모 구간 연결 | 신청 안내상 바로 사용 가능하다. 실제 제공 데이터로 가능한 범위만 구현한다. MVP 의존성은 아니다. |
| 도로 데이터·매칭 모듈 | 같은 도로/방향/층위 판정 | FusedLocation이 이 판정을 자동 제공한다고 가정하지 않는다. 데이터 사용권과 공급자를 별도로 검토한다. |

SDK 개요의 차량 API 퍼미션은 승인된 범위를 전제로 합니다. 기능 문서가 공개됐다는 사실이 계정에서 즉시 사용 가능하다는 뜻은 아닙니다. 신청 안내에는 FusedLocation·TTS·STT·Vehicle Control이 준비 중으로 표시돼 있어, 실제 프로젝트 콘솔 및 공모전 운영 측 확인이 선행돼야 합니다. [SDK 개요](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/) · [사용 신청](https://document.pleos.ai/docs/pleos-only/create-my-project)

### 위치 잠금의 구현 원칙

1. 메모에는 좌표 하나뿐 아니라 방문 대상 도로 구간, 허용 방향, 청취 구역을 저장합니다. MVP는 직접 검수한 소수 구간으로 제한합니다.
2. 위치의 최근성·신뢰도와 연속 관측을 확인합니다. 구간 진입 후보 반경은 초기 50m로 실험하되, 실제 도로 형태와 오차를 보고 조정합니다. 반경만으로 같은 길이라고 판단하지 않습니다.
3. 서버가 상호 팔로우·차단 여부와 방문 조건을 검증한 뒤 제한된 시간의 재생 세션을 발급합니다. 클라이언트도 위치 조건을 지속 확인합니다.
4. 구역 이탈·권한 철회·위치 상실 시 세션을 종료합니다. 장기 다운로드와 원격 다시 듣기는 제공하지 않습니다.
5. 클라이언트 좌표만으로 위치 위조를 완전히 방지할 수는 없습니다. MVP는 시뮬레이션과 실제 위치를 구분하고, 운영 버전은 기기 신뢰 검증과 이동 이상 탐지를 추가 검토합니다.

일반 속도로 통과하는 짧은 구역에서는 30초 메모를 끝까지 듣기 어려울 수 있습니다. 이를 숨기지 않고, 초기에는 안전한 주차 장소가 있는 구간과 짧은 메모를 사용합니다. 추후 도로 길이·이동 속도별 청취 완료율을 검증합니다. 영역 밖에서 재생을 계속하는 편의 기능은 현재 핵심 조건에 맞지 않아 제외합니다.

### 예외 처리와 개인정보

- 위치나 마이크 동의를 거부하면 해당 기능이 동작하지 않는 이유와 설정 경로를 알립니다. 상시 녹음은 하지 않습니다.
- 자신의 전체 이동 이력이나 친구의 현재 위치를 공유하지 않습니다. 방문 인증용 위치의 수집 범위·보존 기간을 설계하며 불필요한 경로 로그는 남기지 않습니다.
- 집·직장 노출이 우려되는 구간은 게시 전 확인하고, 사용자 지정 비공개 구역에서는 게시를 막는 기능을 검토합니다.
- 메모 삭제·신고·차단을 제공합니다. 오디오의 비공개 접근 제어, 파일 크기·길이 제한, 만료된 재생 권한 차단을 구현합니다.
- 오프라인에서는 타인 메모를 새로 해제하지 않습니다. 내 녹음은 로컬 임시 저장 후 연결 복구 시 사용자 확인을 거쳐 게시합니다.
- 내비 안내·통화로 일시정지된 사이 구역을 벗어나면 재생을 재개하지 않습니다. 다시 접근하라고 운전을 재촉하는 안내도 하지 않습니다.

## 6. 기대효과 및 발전 가능성

사용자는 같은 장소를 방문하는 사람과 목소리로 경험을 나눌 수 있습니다. 차량에서는 경로상의 이야기를 발견하고 듣는 과정이 이동 경험과 결합됩니다. 초기에는 친밀한 관계에서 시작해, 검증 후 승인형 드라이브 모임과 지역별 오디오 코스로 확대할 수 있습니다.

초기 실험은 10개 모임·총 30~50명을 대상으로 3개 코스에서 2주간 진행하는 방안을 제안합니다. 다음 수치는 성과가 아닌 실험 통과 기준 초안입니다.

| 지표 | 정의 | 제안 기준 |
|---|---|---|
| 최초 경험 완료 | 초대·상호 팔로우 후 첫 현장 청취까지 마친 참가자 비율 | 50% 이상 |
| 현장 청취 완료율 | 실제 방문으로 시작한 재생 중 80% 이상 들은 비율 | 70% 이상 |
| D7 재사용률 | 첫 현장 청취 후 7일째 다시 핵심 기능을 쓴 참가자 비율 | 30% 이상 |
| 상호 기여율 | 듣기만 하던 참가자가 7일 내 본인 메모도 게시한 비율 | 25% 이상 |
| 구간 판정 오류 | 통제된 경로 테스트에서 다른 도로·구역 밖 해제 여부 | 정의한 필수 시나리오에서 0건 |

예상 MAU는 아직 산정할 근거가 부족합니다. 초기 모임 수 × 모임당 초대 인원 × 가입률 × 월간 현장 사용률로 계산하고, 인터뷰·실험 결과로 가정을 채우겠습니다. 가입자 수를 청취 사용자 수로 취급하지 않겠습니다.

수익화는 재사용이 검증된 뒤 검토합니다. 후보는 모임별 음성 코스 운영 기능과 제작자 코스 판매입니다. 유료여도 현장 청취 조건은 유지합니다. 초기에는 광고나 유료 잠금 해제를 넣지 않습니다.

## 7. 참고자료와 공모전 시연 계획

현재 제출 가능한 앱·APK·영상은 없습니다. 다음 시연을 구현해 기획과 실제 동작을 함께 보여주는 것이 목표입니다.

1. A 계정이 주차 상태에서 메모를 녹음하고 게시합니다.
2. B 계정은 상호 팔로우지만 다른 위치에 있어 듣지 못합니다.
3. B가 같은 구간에 진입하고 청취 가능 상태가 되면 실제 음성이 재생됩니다.
4. B가 구역을 벗어나면 재생이 중단되고 다시 잠깁니다.
5. 같은 위치라도 C 계정은 상호 팔로우가 아니므로 듣지 못합니다.
6. 위치 상실, 잘못된 평행도로, 차단·삭제, 주행 상태 전환에서도 조건이 유지되는지 검증합니다.

시연은 Pleos 에뮬레이터 위치 입력과 실제 SDK 경로를 사용했는지 구분해 표시합니다. 개발용 모의 위치를 실차 검증으로 설명하지 않습니다. 실제 SDK 사용이 막힌 경우 mock 시연과 공식 SDK 검증을 별도 상태로 보고합니다.

## 8. 숏폼 링크

미제작. 선택 참여 시에는 ‘친구가 남긴 목소리를 같은 풍경 앞에서 처음 듣는 순간’을 30~60초 세로 영상으로 보여줍니다. 참여자의 동의를 받은 음성만 사용합니다. 숏폼은 본상 가산점 항목이 아닙니다.

## 내부 개발 준비: 실행 전 확인 사항

사용자가 ‘기획서 먼저’를 요청하여 이 단계에서는 SDK를 설치하거나 프로젝트 계정을 만들지 않았다. 아래는 다음 실행 단계이다.

### 로컬 확인 결과

2026-11-01 확인: 기본 경로 `/Applications/Android Studio.app`, `~/Library/Android/sdk`, `~/.android/avd`가 없다. 다른 경로 설치 여부와 JDK 상태까지 확인한 것은 아니다. 개발 환경 세팅 완료로 보고하지 않는다.

### 세팅 순서와 완료 기준

1. 기존 Android Studio/JDK/SDK 설치 위치와 디스크 공간을 확인한다. 기존 도구를 삭제하지 않는다.
2. Android Studio와 호환 JDK·Gradle 조합을 설치한다. 공식 최소 기준은 Android API28+, Gradle8+, Java/Kotlin이다.
3. Pleos 프로젝트 콘솔에서 실제 SDK 상태를 확인한다. 사용자 로그인·약관 동의·사용 권한이 필요한 단계는 구분한다.
4. Mac용 공식 시스템 이미지 저장소를 등록하고 Pleos Connect Emulator 2.1.0/API34 AVD를 구성한다. RAM4GB, Cold boot, 마이크 입력 및 Virtual Console 설정을 확인한다.
5. 빈 Kotlin 앱을 빌드·설치하고, 위치 콜백과 주차 상태 읽기·마이크 녹음·오디오 포커스를 각각 검증한다.
6. 사용할 수 있는 API를 확인한 뒤 위 MVP 범위를 고정한다. 실사용 불가 API를 형식적으로 호출해 기술 활용성을 주장하지 않는다.

- 가칭은 ‘길소리’이다. 이름·상표 확인은 하지 않았다.
