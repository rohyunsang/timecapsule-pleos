# TC 모바일 앱 구현 및 검증 기록

## 구현 목표
기존 `ym/prototypes/mobile/out`의 79개 화면 시안을 참고하되 최신 정책을 우선한다. 모바일에서도 실제 장소를 방문해 수집할 수 있으며 수집 후에는 차량과 모바일 어디서든 재생한다. AI 요약과 자동 녹취는 구현하지 않는다. Android 에뮬레이터와 Firebase 에뮬레이터는 실행하지 않는다.

## 구성
- `app`: 기존 Pleos 차량 앱
- `shared`: 양쪽에서 사용하는 Firebase 계정, 친구, 캡슐 모델과 동기화 계약
- `mobile`: 별도 설치 가능한 Android Compose 모바일 앱

## 2026-11-10 음성 답장 및 차량 연결 구현 기록
- 사용자 확정 정책: 기본은 녹음 장소에서 수집 후 듣기다. 작성자가 ‘3일 후 어디서든 듣기’를 선택하면 서버가 전송을 수락한 시점부터 72시간 후 방문 없이 재생한다. 이 경우 물리적 수집 기록을 만들지 않는다.
- 모바일에 답장 방식 선택, 마이크·정확한 위치 권한 안내 및 설정 이동, 최대 1분 녹음, 3초 미만 녹음 제외, 화면 이탈 시 녹음 종료, 완료한 녹음의 로컬 임시 보관, 재전송과 삭제 확인을 추가했다.
- 답장은 원본 작성자에게만 보낸다. 재전송은 같은 문서 ID를 사용하고, 음성과 서버 전송 시각을 하나의 트랜잭션으로 최초 한 번만 저장한다. 시간 미확정 상태는 잠금으로 처리한다.
- 차량은 잠긴 답장의 메타데이터를 먼저 받아 개봉 시각을 표시하고, 개봉 후 음성을 내려받는다. 답장은 서버 권한 확인 후 재생하며 다른 친구에게 전달하거나 공개 범위를 바꾸지 않는다.
- 공유 대상 선택, 수집한 친구 캡슐의 전달, 앨범 편집·공유, 차량의 비공개 백업 선택, 수집 기록 양방향 동기화와 목적지 수신 확인을 연결했다. 실제 서버 간 동작은 아직 검증하지 않았다.
- `:mobile:assembleDebug :mobile:lintDebug :app:assembleDebug :app:testDebugUnitTest :shared:testDebugUnitTest` 통과. 단위 테스트는 98개이며 실패·오류는 0개다. SQLite 메모리 DB에서 5→6 열 추가 후 생성된 Room 스키마와 열·타입·nullable 속성을 비교했다.

## 2026-11-10 목적지 처리 결과와 지도 상태
- 모바일 지도 마커와 대체 목록에 개봉 대기·현장 수집·재생 가능 상태를 반영했다. 색상뿐 아니라 시계·자물쇠·재생 도형으로 구분한다. 수집 또는 개봉 상태가 바뀌어도 사용자가 이동한 지도 카메라는 초기화하지 않는다.
- 지도 마커 생성 함수의 실제 비트맵을 Paparazzi로 렌더링하고 육안 및 이미지 비교로 확인했다. 네트워크 지도 타일과 지도 제스처의 실제 기기 검증은 아직 남아 있다.
- 모바일 캡슐 상세에 차량 목적지 요청 상태를 표시하고 같은 캡슐의 미처리 요청이 있으면 중복 전송을 막는다. ‘확인됨’은 내비게이션 경로 완성의 증거로 표시하지 않는다.
- 차량의 목적지 확인 결과를 계정별로 로컬 보관하고 연결 복구 후 재전송한다. 전송 대기 결과가 있는 요청은 앱을 다시 시작해도 확인창에 반복 표시하지 않는다. 서버 상태 변경은 pending에서 한 번만 허용하도록 트랜잭션과 규칙을 보강했다. 실제 연결 끊김·복구 및 규칙 검증은 서버 연결 후 수행한다.
- LifecycleRegistry의 observer 등록은 현재 상태까지 이벤트를 전달하므로 별도 onStart/onResume 중복 호출을 제거했다.

## 2026-11-10 음성 답장 미리 듣기와 임시 보관 검증
- 답장 전송 전에 녹음한 내용을 미리 듣고 정지할 수 있다. 삭제·전송·작성창 닫기 시 미리 듣기를 멈춘다. 성공한 전송만 작성창을 닫으며 실패하면 임시 녹음과 작성창이 유지된다.
- 녹음 시작 전 오디오 포커스를 확보하고, 포커스를 잃으면 녹음을 마치도록 연결했다. 짧아서 보관하지 못한 녹음을 보관 완료로 안내하지 않는다. 실제 통화/마이크 중단은 기기 검증이 남아 있다.
- AtomicFile 임시 보관을 별도 저장 객체로 분리했다. 저장 공간 부족 시 완료한 녹음을 메모리에 유지하되, 저장 완료로 표시하지 않고 앱을 닫기 전 전송이 필요함을 알린다. AtomicFile 복원 경로도 사용한다.
- Layoutlib 테스트에서 저장 객체를 다시 만들어도 작성자·수신자·개봉 방식·파일을 복원하는지, 다른 계정의 답장을 읽거나 삭제하지 않는지, 파일 유실 시 전송 가능한 답장으로 복원하지 않는지를 확인했다. 녹음 장치나 Android 에뮬레이터는 실행하지 않았다.
- 답장 작성창 내용을 스크롤할 수 있도록 해 작은 화면에서도 작업 버튼에 접근할 수 있게 했다.
- 모바일 빌드·lint·이미지 비교를 통과했다. 현재 단위/저장/렌더링 테스트는 총 108개이며 실패·오류는 없다.

## 네트워크 재시도 시 중복 생성 방지 (2026-11-10)

- 요청 ID 재사용·계정 분리·처리 완료 후 새 요청·로컬 보관 실패를 단위 테스트했다. 테스트 저장 매체는 메모리이며 Android 프로세스 종료 및 실제 SharedPreferences 디스크 동작을 검증한 것은 아니다.
