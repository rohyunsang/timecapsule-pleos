# 타임캡슐 주행 UX 리서치 및 수정 제안

작성일: 2026-11-01. 대상: 네이티브 앱 0.1.0, 현재 기획서, 기존 Pleos 에뮬레이터 검증 화면.

현재 앱은 기능 시연에 필요한 연결을 갖췄지만, 운전자가 화면을 보지 않고 청취를 시작·중단·재개하는 경험은 보완해야 한다. 최우선 변경은 장소 잠금의 의미, 차량 미디어 제어, 중단 후 복구 방식이다.

이번 작업은 공식 지침 및 선행 연구를 읽고 구현과 대조한 데스크 리서치다. 운전자 인터뷰, 사용성 실험, 실차 검증을 수행한 결과는 아니다. 기존 시험은 SDK와 기능 동작을 증명하며 운전자의 주의 분산 정도를 증명하지 않는다. 앱 코드, APK, 제출 기획서는 이번 검토에서 변경하지 않았다.

## 유지할 설계

- 주행 청취 기본값을 꺼 두고 주차 중 명시적으로 켜도록 한 점을 유지한다.
- 녹음·공개일 설정·삭제는 주차 중에만 제공한다. 정체나 신호 대기의 속도 0을 주차로 취급하지 않는다.
- 녹음 전 동승자에게 설명하고 동의를 확인하는 흐름, 시작·종료 알림음, 로컬 저장을 유지한다.
- 내비·통화·운전 관련 신호를 우선하며, 사용자 중지 명령 후 임의로 재개하지 않는다.
- 플랫폼의 주행 화면 차단을 우회하지 않는다.

## 우선순위별 수정사항

P0는 다음 차량 시연 전에 동작 기준을 정하고 수정해야 하는 항목이다. P1은 운전자 평가 전에 보강할 항목이다. 아래 위험 설명 중 사용자 행동에 관한 부분은 코드에서 도출한 가설이며 실제 관찰 결과가 아니다.

### P0-1. 장소를 벗어나는 순간 끊기는 정책을 다시 정한다

현재 `CapsulePolicy.kt:7,18`은 반경 100m 안에서만 열도록 하고, `CapsuleEngine.kt:251`은 재생 중에도 같은 조건을 검사하여 구역 이탈 시 청취 전체를 종료한다.

일정 속도로 원의 중심을 통과한다고 가정하면 구역 내 최대 이동 거리는 200m다. GPS 지연과 안내 시간을 제외해도 30km/h에서 24초, 50km/h에서 14.4초, 100km/h에서 7.2초다. 중심에서 벗어나 통과하면 더 짧다. 최대 30초 캡슐을 끝까지 듣기 어려우며, 사용자가 소리를 놓치지 않으려고 감속·정차·우회할 가능성을 검증해야 한다.

**권고:** “그 길에 가야 열린다”는 조건을 유지하되, 현장 진입으로 열린 한 캡슐은 현재 청취 세션에서 마저 들을 수 있게 한다. 원격 영구 해제나 무제한 다시 듣기를 뜻하지 않는다. 장소 이탈 이후의 완료 허용은 기존 기획을 바꾸는 제품 결정이므로 승인된 규칙으로 확정한 뒤 구현한다.

엄격히 구역 안에서만 들어야 한다면 안전하게 주차할 수 있는 장소 중심으로 서비스 범위를 바꾸는 대안이 있다. 도로 위 재생을 유지하면서 반경만 무작정 넓히는 방식은 다른 도로에서 열리는 문제를 키운다.

### P0-2. 화면 없이 중단하고 이어 들을 수 있게 한다

기존 release 화면 `evidence/10-release-moving.png`에서 Pleos가 앱 화면을 차단한다. 따라서 앱 내부의 큰 ‘소리 끄기’ 버튼은 주행 제어의 보장 수단이 아니다. 알림을 찾아 열도록 하는 흐름도 운전자의 시선을 요구한다.

`PlaybackService.kt:22`에는 MediaSession의 pause·stop만 있고 play·재개·탐색 서비스가 없다. pause도 세션 전체를 끈다. 현재 핸들 버튼의 실제 동작은 검증되지 않았다.

**권고:** 표준 차량 미디어 서비스와 연결하여 핸들 버튼으로 일시정지·재개·건너뛰기를 제공한다. 잠긴 콘텐츠를 미디어 ID나 음성 검색으로 우회 재생하지 않도록 모든 경로에 동일한 권한·현장 조건을 적용한다. 핵심 사용 가치가 청취이므로 Music/Audio 분류를 우선 검토하되, 위치 기반 개인 음성 기록에 맞는 하위 분류는 운영 측 확인 항목으로 남긴다. 카테고리 변경만으로 주행 허용을 얻는 것은 아니다. 근거: [Pleos Music/Audio 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/music-audio-app-developement-guide).

### P0-3. 잠깐 멈춤과 청취 종료를 구분한다

현재 `CapsuleEngine.kt:237`은 GAIN 이외의 포커스 변경에 `armed=false`와 플레이어 해제를 적용한다. `:255`는 방향지시등·위치 조건 변경도 같은 방식으로 처리한다. `:231`은 재생 시작 즉시 들은 캡슐로 표시한다. 따라서 한 문장도 마치지 못한 캡슐이 자동 대기 목록에서 빠지고, 정차 후 조작이 필요해진다.

**권고:** 청취 세션, 재생 위치, 일시정지 사유, 청취 완료 여부를 따로 저장한다. 내비 안내와 방향지시등에는 재생 위치를 보존하고, 신호가 끝났다고 즉시 소리를 다시 내지 않는다. 기본 재개는 핸들 버튼 등 명시적 입력으로 한다. 일시 중단 후 자동 복귀 옵션은 포커스·차량 조건을 다시 검사하는 별도 실험 대상으로 둔다. 사용자가 중지했거나 프로필이 바뀌면 자동 재개하지 않는다. 구역 밖 재개 가능 여부는 P0-1 결정과 일치시킨다. 근거: [Google 상호작용 원칙](https://developers.google.com/cars/design/design-foundations/interaction-principles), [Pleos 포커스 정책](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/audio-focus-development-guide/audio-focus-development).

### P0-4. 플랫폼 주행 제한과 앱의 보수적 제한을 함께 적용한다

현재 `CapsuleEngine.kt:157`과 `MainActivity.kt:143`은 기어 기반으로 UI를 구분한다. CarUxRestrictions 연동은 없다. 기어·방향지시등만으로 교차로·합류·급제동 등 운전자 부담을 모두 알 수는 없다.

**권고:** CarUxRestrictions 변경을 구독하고 앱의 주차 전용 규칙과 함께 적용한다. 상태가 불명확하면 새 청취를 시작하지 않는다. 일시 중단과 데이터 상실을 구분하여 상태 복구 뒤 임의 재생하지 않는다. 속도·조향·브레이크·내비 이벤트는 실제 지원 값과 지연을 확인한 뒤 보조 조건으로 사용한다. “방향지시등이 꺼졌으니 안전하다”는 판정은 하지 않는다. 근거: [Pleos 주행 규제 개발 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide).

### P1-1. 갑작스러운 재생과 연속 재생을 줄인다

현재 `CapsuleEngine.kt:126`은 조건에 맞는 첫 캡슐을 바로 재생하고, 완료되면 다음 검사 주기에 다음 캡슐을 재생할 수 있다. 같은 장소에서 방금 만든 캡슐도 대상이 된다. 진입 이벤트 자체를 요구하지 않는다.

**권고:** 주차 중 오늘 들을 대상과 재생 방식을 선택한다. 최초 경험은 ‘알림 후 재생 선택’을 기본 후보로 시험하고, 자동 듣기는 별도 명시적 선택으로 제공한다. 주행 중 답변을 재촉하거나 무응답을 동의로 처리하지 않는다. 방금 녹음한 캡슐은 다음 방문 전까지 자동 대상에서 제외하고, 여러 캡슐이 겹치면 한 번에 하나만 제안한다. 재안내 횟수와 간격은 운전자 평가로 정한다.

오랜 가족의 목소리가 반갑거나 갑작스럽게 느껴질 수 있다는 것은 이 제품에서 검증할 가설이다. AAA 연구가 가족 추억 음성의 감정 효과를 직접 입증한 것은 아니다. 특별한 편지·타인 공유 음성은 주차 중 청취를 선택할 수 있게 한다.

### P1-2. ‘이 주행’의 시작과 끝을 정의한다

현재 `armed`와 `playedThisSession`은 프로세스 메모리에 있다. UI는 ‘이 주행’이라고 하지만 운행 종료·장시간 주차·프로필 변경을 기준으로 세션을 관리하지 않는다. 같은 프로세스가 유지되면 청취 대기가 예상보다 오래 지속되거나 다음 여행에서 이미 들은 것으로 남을 수 있다.

**권고:** 출발 전 명시적 시작, 사용자 종료, 검증된 차량 전원·프로필 이벤트에 따라 세션을 관리한다. 전원 이벤트를 사용할 수 없다면 보수적인 만료와 다음 사용 시 재확인을 정의한다. ‘일시정지’와 ‘이번 주행 듣기 종료’를 구분하고, 위치 감시 종료도 일치시킨다. 잠깐 P단으로 바뀔 때마다 새 여행으로 처리하지 않는다.

### P1-3. ‘같은 길’의 판정을 보강한다

현재 판정은 좌표 간 직선거리이며 도로 식별·진행 방향·평행 도로·고가도로를 구분하지 않는다. 위치가 유효하고 최신이어도 같은 도로라는 뜻은 아니다.

**권고:** SDK가 제공하는 정확도 의미를 확인하고, 가능한 경우 도로 매칭과 연속 위치로 실제 통과를 판단한다. 경계에서 신호가 흔들릴 때 반복 안내가 생기지 않게 진입·이탈 상태를 구분한다. 판정이 불확실하면 재생을 보류한다. 도로 매칭 구현 전에는 ‘같은 길 확인’ 대신 ‘저장 위치 주변 확인’으로 기능을 설명한다. 판정 오차를 해결하기 위해 운전자에게 유턴이나 경로 변경을 요구하지 않는다.

### P1-4. 녹음 중 출발하더라도 기록 유실을 최소화한다

현재 `CapsuleEngine.kt:252`는 녹음 조건이 바뀌면 `finishRecording(false)`를 호출하여 녹음을 삭제한다. `MainActivity.kt:44`도 화면 이탈 시 취소한다.

**권고:** 이미 명시적으로 동의하고 시작한 녹음은 출발 순간 즉시 중단하되, 유효한 앞부분을 로컬 임시보관하고 다음 주차 때 저장·삭제를 선택하게 한다. 주행 중 확인창이나 재녹음을 유도하지 않는다. 사용자가 명시적으로 취소한 녹음은 삭제한다. 임시보관 정책은 사전에 설명하고, 잘못된 위치로 정식 캡슐을 만들지 않는다.

### P1-5. 정차 화면을 출발 준비와 추억 관리로 구분한다

현재 release 화면은 녹음이 가장 강조되고, 청취·공개일·목록 삭제가 한 화면에 섞여 있다. ‘열리는 날 · 지금 / 1년 뒤’ 버튼은 실제 선택값을 계속 보여주지 않는다. 배경은 고정 다크 테마다.

**권고:** 첫 화면의 주 행동을 ‘이번 주행에서 듣기’로 두고 녹음과 관리는 별도 영역으로 구분한다. 녹음 화면에는 선택한 개봉일을 명확히 표시한다. 출발 전 설명은 짧은 요약과 필요할 때 보는 상세 설명으로 나눈다. 주행 중 미디어 화면은 제목·재생 상태·기본 제어로 한정하고 거리 카운트다운·파형 애니메이션·목록·팔로우 알림을 넣지 않는다. 개발용 연결 문자열은 진단 화면으로 옮긴다. 주간 역광, 야간, 실제 착좌 거리에서 가독성을 검증한다. 근거: [Pleos UI 디자인](https://document.pleos.ai/docs/connect/guide/docs-design/Introduction/intro).

## 제안하는 사용 흐름

| 상황 | 운전자 경험 | 앱의 처리 |
|---|---|---|
| 주차·출발 준비 | 오늘 들을 대상과 청취 방식을 선택한다. | 권한·위치·주행 제한 상태를 확인하고 세션을 시작한다. 경로 연동 전에는 경로상의 캡슐 수를 아는 것처럼 표시하지 않는다. |
| 일반 주행 | 내비 화면을 유지한다. | 앱 화면을 강제로 열지 않고, 허용된 미디어 기능만 유지한다. |
| 캡슐 주변 진입 | 선택한 방식에 따라 짧은 제안 또는 재생을 받는다. 무응답이어도 불이익이 없다. | 개봉 조건과 차량 상태를 다시 확인한다. 안전 관련 음성이 우선이다. |
| 내비·통화·방향지시등 | 음성이 멈춘다. 화면에서 원인을 찾지 않아도 된다. | 재생 위치와 보류 사유를 보존한다. 즉각적인 추가 설명 음성도 겹쳐 내지 않는다. |
| 이어 듣기 | 검증된 핸들 버튼 등으로 재개한다. | 조건을 다시 확인한다. 장소 이탈 후 재개는 확정된 개봉 정책을 따른다. |
| 도착·주차 | 못 들은 캡슐과 임시 녹음을 확인한다. | 관리 기능을 복원하고 청취 세션을 종료한다. 장소 조건을 충족하지 않은 캡슐을 임의로 열지는 않는다. |

## 검증 계획

먼저 Pleos 에뮬레이터에서 아래 기능을 확인하고, 운전자 평가는 별도의 운전 시뮬레이터에서 진행한다. Pleos 에뮬레이터의 차량 속도 입력은 실제 주의 분산 측정 도구가 아니다.

1. 정상·평행 도로·위치 누락·경계 흔들림에서 잘못된 개봉과 중복 안내가 발생하는지 확인한다.
2. 내비·통화·긴급음·Gleo 개입 전후의 미디어 상태와 사용자 중지 후 비자동 재개를 확인한다.
3. 핸들 버튼의 pause·play·stop·skip과 잠긴 캡슐의 우회 접근 차단을 확인한다.
4. 30·50·100km/h 위치 재생 시험으로 구역 이탈 정책과 30초 캡슐 완료를 확인한다. 이는 사용성 안전 인증이 아니다.
5. 출발 중 녹음 중단, 프로필 변경, 전원 전환, 앱 재시작 뒤 상태와 위치 감시 종료를 확인한다.
6. 초기 형성 평가로 운전자 6~8명을 모집해 주차 준비, 갑작스러운 제안, 일시 중단, 재개, 듣기 종료 과제를 시험한다. 일반 운전·수동적으로 오디오를 듣는 조건과 비교하고 순서를 교차 배치한다. 이 인원수는 문제 발견을 위한 제안이며 통계적 안전성 입증 표본이 아니다.
7. 화면 주시 시간, 조작 횟수·오조작, 재개 성공률, 제동 반응·차로 유지(측정 가능한 시뮬레이터), 주관적 부담, 놓칠까 봐 감속하고 싶은 정도를 기록한다. 주행 중 생각을 말하게 하는 절차는 부담 측정을 교란하므로 인터뷰는 과제 뒤에 한다.

## 기획서에 반영할 문장

“타임캡슐은 주차 중 녹음하고 청취를 준비하며, 주행 중에는 차량의 표준 미디어 제어로 짧은 음성을 듣는 앱입니다. 운전자가 청취를 중단해도 진행 상태를 보존하며, 장소를 놓칠까 봐 감속하거나 화면을 조작하도록 유도하지 않습니다.”

이 문장은 목표 UX다. 표준 미디어 서비스·재개 기능을 구현하기 전에는 구현 완료 설명으로 사용하지 않는다. ‘방문 시 1회 개봉 후 현재 세션에서 완료 허용’ 정책을 채택할 경우 기존 기획서의 ‘구역 이탈 즉시 중단’ 문장도 함께 변경해야 한다.
